# PXE-0074: v7.0.1 Operator And Media Recovery

The v7.0.1 patch packages the bounded operator fixes completed after the v7.0.0
local/demo baseline. Model upload outcomes preserve artifacts and distinguish
collisions from active-store or validation failures. The sidebar now uses the
typed, confirmed, audited restart action. Routine transport and tracker badges
follow OSD visibility, and WebRTC uses separate progress deadlines rather than
one timer spanning signaling through first decoded frame.

An authenticated probe of the still-running lab process exposed a
mixed-generation state: updated dashboard files were talking to a backend
started before the manual-restart correction. The old backend truthfully
returned `no_pending_system_restart_changes`; it cannot acquire new Python
behavior until one host-side stop/start. Current source allows manual restart
without pending configuration for maintained launchers, while retaining the
administrator, policy, flight-state, audit, confirmation, and idempotency
barriers. The compatibility message now explains the required host action.

Active QGC documentation now points to the focused #14727 through #14731
sequence and treats PixEagle as one example source. The HTTP and WebSocket
transport proposals remain unauthenticated. Bearer headers, Origin, custom CA,
token lifecycle, and recording policy are explicitly deferred rather than
partially implemented.

The maintained backend passed `3,618` tests with expected optional skips, Phase
0 passed `492`, and the dashboard passed `59` suites / `392` tests plus lint and
production build. Generated schema/API context, compile, shell, and diff checks
also pass. Public WebRTC, target hardware, PX4, simulation, camera/gimbal,
field, and aircraft acceptance remain separate evidence gates.
