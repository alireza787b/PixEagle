# Canonical native-only transition baseline

The accepted report-owned prepare/observe/archive flow is extracted into one
canonical simulator-only runner with shared source-built image/model/world,
original CID/token ownership, production native observer and stable predicate.
The fixed observer sidecar preserves its ROS workspace and joins only the
verified primary's network namespace. Startup source-bound parameter overlays
and readback replace the historical mid-run MIS cache barrier in new fresh
rootfs captures; all old helpers, failed runs and raw evidence remain unchanged.

The fixed 2 m full-window gate, native freshness/envelope and logger profile
remain intact. Earlier performance failure does not reset the reference or
prevent a separately healthy inverse diagnostic; rescue/unknown/takeover or
unsettled state does. Closed ULog estimator and ground-truth data are required.
Observer/flush failures still reach cleanup of the two original owned CIDs,
with no mode write or pursuit request during teardown.

Independent draft review reproduced two admission gaps: a stopped sidecar
could pass identity-only inspection, and a last-moment target-phase switch
could borrow the previous phase's seven samples. Both now have explicit checks
and synthetic regression cases. Startup freshness waits within the same bounded
preflight deadline; positive authority/identity/rescue failures remain failures.

Validation is mock/software only: the exact focused command and existing CI
selection are documented in `native/native-transition-baseline.md`. No Docker
runtime, simulator, image build, flight, hardware or configuration mutation was
performed. Root review and a separately approved actual capture remain required.
